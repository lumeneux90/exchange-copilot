# Модель правил ИИ-участников рынка

Черновик для обсуждения поведения synthetic users, treasury и оркестратора событий. Цель документа — не зафиксировать финальные параметры, а дать понятные модели, которые можно править перед реализацией.

## 1. Базовая идея

Технически все участники рынка остаются обычными `User` с финансовыми счетами и заявками в общем CLOB.

```prisma
enum UserKind {
  HUMAN
  TREASURY
  AI_AGENT
}
```

- **HUMAN** — реальный пользователь.
- **TREASURY** — казна и стабилизатор экономики.
- **AI_AGENT** — synthetic user: маркет-мейкер, розничный трейдер, momentum-трейдер, whale и т.п.

Отдельная таблица профилей на MVP не нужна. Характеры агентов задаются в коде по `login`.

## 2. Варианты пар

| Пара        | Роль                                      |
| ----------- | ----------------------------------------- |
| `USD/USDT`  | Мост между фиатным счётом и крипто-спотом |
| `BTC/USDT`  | Главная крипто-пара                       |
| `ETH/USDT`  | Вторая базовая крипто-пара                |
| `BNB/USDT`  | Биржевой токен как узнаваемый актив       |
| `SOL/USDT`  | Более волатильная крипто-пара             |
| `DOGE/USDT` | Мем-актив и источник шума                 |
| `TON/USDT`  | Популярный региональный актив             |
| `XCP/USDT`  | Главный крипто-рынок собственного токена  |
| `XCP/RUB`   | Локальный рынок собственного токена       |
| `XCP/USD`   | Фиатный рынок собственного токена         |

## 3. Что такое `xcpInterest`

`xcpInterest` — это склонность агента интересоваться XCP.

Это не отдельная сущность в БД, а параметр в коде от `0` до `1`.

| Значение | Поведение                                              |
| -------- | ------------------------------------------------------ |
| `0.0`    | Агент почти игнорирует XCP                             |
| `0.3`    | Иногда торгует XCP как обычным альтом                  |
| `0.6`    | Держит XCP в watchlist и часто реагирует на события    |
| `0.9`    | Считает XCP главным активом, чаще покупает/продаёт его |

Пример: если оркестратор даёт режим `xcp_hype`, агент с `xcpInterest = 0.8` с высокой вероятностью пойдёт в `XCP/USDT`, `XCP/USD` или `XCP/RUB`, а агент с `xcpInterest = 0.1` может вообще не отреагировать.

## 4. Оркестратор событий

Один LLM-оркестратор выбирает рыночный режим, но не создаёт конкретные ордера.

Он получает snapshot:

- последние цены;
- spread и глубину стакана;
- объём за 5/30/60 минут;
- долю сделок `HUMAN`, `AI_AGENT`, `TREASURY`;
- резервы treasury;
- давление покупки/продажи по XCP;
- прошлый режим.

Он возвращает JSON:

```json
{
  "mode": "xcp_treasury_support",
  "durationMinutes": 30,
  "riskAppetite": 0.42,
  "xcpAttention": 0.7,
  "volatilityMultiplier": 1.2,
  "liquidityMultiplier": 1.25,
  "retailBias": "buy_dips",
  "treasuryBias": "support"
}
```

Этот JSON валидируется кодом. Если ответ не проходит схему или нарушает лимиты, используется fallback-режим `balanced_market`.

### Допустимые значения `retailBias`

`retailBias` управляет synthetic users уровня retail: мелкие пользователи, покупатели просадок, momentum-участники и часть cross-market трейдеров. Это не команда всем покупать или продавать, а мягкое смещение вероятностей.

Для MVP достаточно пяти режимов:

| Значение     | Смысл                      | Как влияет на агентов                                          |
| ------------ | -------------------------- | -------------------------------------------------------------- |
| `neutral`    | Нет явного перекоса        | BUY/SELL выбираются по базовым правилам профиля                |
| `accumulate` | Розница накапливает риск   | Чаще покупает, особенно активы с вниманием рынка и XCP         |
| `distribute` | Розница разгружает позиции | Чаще продаёт часть активов и фиксирует прибыль                 |
| `risk_off`   | Розница снижает риск       | Меньше заявок, меньше размер, чаще продажа волатильных активов |
| `buy_dips`   | Розница покупает просадки  | Покупатели просадок активнее, retail чаще ставит buy ниже mid  |

Пример: `retailBias = "buy_dips"` не означает, что каждый агент обязан купить. Это значит, что при наличии просадки и свободного USD/RUB вероятность покупки повышается.

### Допустимые значения `treasuryBias`

`treasuryBias` управляет только treasury policy. Это режим поведения казны на рынках XCP. Treasury всё равно соблюдает `minReserve`, дневные caps, лимиты размера и максимальную долю своего участия в рынке.

Для MVP достаточно пяти режимов:

| Значение   | Смысл                       | Как влияет на treasury                                             |
| ---------- | --------------------------- | ------------------------------------------------------------------ |
| `neutral`  | Обычное поддержание стакана | Держит bid/ask вокруг fair band без перекоса                       |
| `support`  | Поддержка XCP               | Увеличивает buy-заявки, но не ниже min reserve и не выше daily cap |
| `cooldown` | Охлаждение перегретого XCP  | Увеличивает sell-заявки, когда XCP быстро растёт или ask пустой    |
| `conserve` | Сберегающий режим           | Расширяет spread, уменьшает размер, бережёт резервы                |
| `pause`    | Пауза интервенций           | Не ставит новые treasury-заявки, кроме отмены устаревших           |

Пример: `treasuryBias = "support"` при пустом bid и здоровом USD-резерве даст buy-уровни в `XCP/USD`. Если резерв ниже минимума, treasury не покупает даже в этом режиме.

## 5. Общий цикл runner

Фоновый runner выполняется раз в N секунд.

```txt
1. Прочитать активный market mode.
2. Прочитать пары, стаканы, последние сделки и балансы агентов.
3. Отменить устаревшие заявки AI/TREASURY.
4. Выбрать подмножество активных synthetic users на этот тик.
5. Для каждого агента применить его rule policy.
6. Создать лимитные заявки через общий CLOB.
7. Записать метрики.
```

Важно: не все AI users активны каждый тик. Можно иметь 100 профилей, но будить 10-20 за проход.

## 6. Treasury Policy

Treasury работает только с XCP на MVP:

- `XCP/USDT`
- `XCP/USD`
- `XCP/RUB`

Цель treasury — поддерживать ликвидность XCP и возвращать фиат в экономику, не истощая резервы.

Параметры:

```ts
type TreasuryPolicy = {
  minUsdReserve: number;
  minRubReserve: number;
  maxUsdSpendPerTick: number;
  maxRubSpendPerTick: number;
  maxUsdSpendPerDay: number;
  maxRubSpendPerDay: number;
  maxXcpSellPerTick: number;
  targetSpreadBps: number;
  maxOpenOrdersPerPair: number;
};
```

Правила:

| Ситуация                                | Действие                                            |
| --------------------------------------- | --------------------------------------------------- |
| Bid-сторона XCP пустая                  | Поставить лимитный `BUY`, если резерв выше минимума |
| Ask-сторона XCP пустая                  | Поставить лимитный `SELL`, если есть XCP            |
| Human sell pressure высокий             | Покупать XCP в рамках дневного cap                  |
| XCP быстро растёт                       | Продавать немного XCP в силу роста                  |
| Резерв USD/RUB ниже минимума            | Остановить buy-интервенции                          |
| Доля treasury в сделках слишком высокая | Снизить размер заявок                               |

Treasury не должен гарантировать цену. Он только поддерживает рынок в пределах бюджета.

## 7. Единый профиль synthetic user

Для MVP не нужны отдельные типы с разными полями для retail, market maker, dip buyer, momentum и whale. Все synthetic users описываются одним простым профилем. Различия задаются `archetype` и разными значениями одних и тех же полей.

```ts
type SyntheticTraderArchetype =
  | "MARKET_MAKER"
  | "RETAIL"
  | "DIP_BUYER"
  | "MOMENTUM"
  | "WHALE";

type SyntheticTraderProfile = {
  login: string;
  archetype: SyntheticTraderArchetype;
  enabled: boolean;
  preferredPairs: string[];
  activityRate: number; // 0..1

  // Размер и частота риска.
  orderSize: number; // 0..1
  maxOrderShare: number; // 0..1
  maxOpenOrders: number;

  // Характер поведения.
  riskTolerance: number; // 0..1
  xcpInterest: number; // 0..1
  patience: number; // 0..1
  trendSensitivity: number; // 0..1
  dipSensitivity: number; // 0..1
  liquidityRole: number; // 0..1
  randomness: number; // 0..1
};
```

`archetype` нужен не потому, что у агента отдельная схема, а чтобы быстро задать дефолтные веса. Например:

| Archetype      | Типичный профиль                                                      |
| -------------- | --------------------------------------------------------------------- |
| `MARKET_MAKER` | Высокий `liquidityRole`, средний `riskTolerance`, низкий `randomness` |
| `RETAIL`       | Средняя случайность, небольшие заявки, умеренный риск                 |
| `DIP_BUYER`    | Высокий `dipSensitivity`, высокая `patience`                          |
| `MOMENTUM`     | Высокий `trendSensitivity`, низкая/средняя `patience`                 |
| `WHALE`        | Низкий `activityRate`, высокий `orderSize`, высокая `patience`        |

Один агент может быть смешанным. Например retail с высоким `dipSensitivity` иногда покупает просадки, но не превращается в отдельный тип.

### Значение полей

| Поле               | Смысл                                                                     |
| ------------------ | ------------------------------------------------------------------------- |
| `activityRate`     | Как часто агент вообще пытается действовать                               |
| `orderSize`        | Типичный размер заявки относительно капитала агента                       |
| `maxOrderShare`    | Максимальная доля свободного баланса, которую можно вложить в одну заявку |
| `maxOpenOrders`    | Сколько открытых заявок агент может держать                               |
| `riskTolerance`    | Готовность покупать волатильные активы и увеличивать размер               |
| `xcpInterest`      | Насколько агент интересуется XCP                                          |
| `patience`         | Склонность ставить лимитки дальше от рынка и ждать                        |
| `trendSensitivity` | Насколько агент реагирует на рост/падение цены                            |
| `dipSensitivity`   | Насколько агент любит покупать просадки                                   |
| `liquidityRole`    | Насколько агент похож на поставщика ликвидности                           |
| `randomness`       | Насколько часто агент делает шумные/неидеальные действия                  |

### Как профиль превращается в действие

На каждом тике runner выбирает активных агентов и строит действие из этих параметров:

| Условие                    | Что меняется                                               |
| -------------------------- | ---------------------------------------------------------- |
| Высокий `liquidityRole`    | Агент чаще ставит заявки с обеих сторон стакана            |
| Высокий `dipSensitivity`   | Агент чаще покупает актив после просадки                   |
| Высокий `trendSensitivity` | Агент чаще покупает рост или продаёт падение               |
| Высокий `patience`         | Агент ставит цену дальше от рынка и дольше ждёт исполнения |
| Высокий `randomness`       | Агент чаще выбирает неидеальную пару, цену или сторону     |
| Высокий `xcpInterest`      | Агент чаще выбирает `XCP/USD` и `XCP/RUB`                  |

Дальше выбирается одно или несколько действий с учётом:

- свободных балансов;
- `retailBias`;
- активного market mode;
- `xcpInterest`;
- лимитов размера и числа открытых ордеров;
- текущего spread и глубины стакана.

Пример: `retailBias = "buy_dips"` усиливает эффект `dipSensitivity`, а `retailBias = "risk_off"` снижает эффективные `activityRate`, `orderSize` и вероятность покупки волатильных активов.

`orderSize` и `maxOrderShare` намеренно не привязаны к USD. Runner сам переводит их в конкретный объём пары через доступный баланс и ориентирную цену. Например агент с `orderSize = 0.2` и свободными `1000 USDT` может поставить заявку примерно на `200 USDT`, но если `maxOrderShare = 0.1`, размер будет ограничен `100 USDT`.

### Примеры профилей

```ts
const syntheticTraderProfiles: SyntheticTraderProfile[] = [
  {
    login: "ai_maker_xcp",
    archetype: "MARKET_MAKER",
    enabled: true,
    preferredPairs: ["XCP/USD", "XCP/RUB"],
    activityRate: 0.9,
    orderSize: 0.12,
    maxOrderShare: 0.18,
    maxOpenOrders: 8,
    riskTolerance: 0.45,
    xcpInterest: 0.9,
    patience: 0.8,
    trendSensitivity: 0.2,
    dipSensitivity: 0.35,
    liquidityRole: 0.95,
    randomness: 0.05,
  },
  {
    login: "ai_retail_02",
    archetype: "RETAIL",
    enabled: true,
    preferredPairs: ["BTC/USDT", "SOL/USDT", "XCP/USDT"],
    activityRate: 0.25,
    orderSize: 0.05,
    maxOrderShare: 0.12,
    maxOpenOrders: 2,
    riskTolerance: 0.65,
    xcpInterest: 0.55,
    patience: 0.35,
    trendSensitivity: 0.25,
    dipSensitivity: 0.3,
    liquidityRole: 0.05,
    randomness: 0.45,
  },
];
```

Такой формат оставляет один тип для всех AI users и позволяет добавлять новых участников простым копированием профиля с другими числами.

## 8. Cross-Market Stock Trader

Эти же AI users могут торговать акциями в портфельном модуле.

Смысл: synthetic user живёт не только на споте, а как участник всей платформы.

Правила связи:

| Ситуация                                  | Действие                                 |
| ----------------------------------------- | ---------------------------------------- |
| Хочет купить акции, но не хватает RUB/USD | Продаёт часть XCP или крипты на споте    |
| Получил прибыль на акциях                 | Может купить XCP или крипту              |
| Просадка портфеля                         | Повышает вероятность продажи XCP за фиат |
| XCP нужен для доступа/лимитов             | Покупает XCP перед активностью           |

На MVP можно не запускать полноценный cross-market loop. Достаточно заложить правило: часть AI users иногда продаёт XCP, потому что им нужен фиат для акций. Это поддерживает главный круговорот economy-model.

## 10. Инварианты безопасности

- AI/TREASURY не могут создавать заявки без свободного баланса.
- AI/TREASURY используют тот же CLOB, что и human users.
- LLM не создаёт прямые ордера.
- Все решения проходят caps.
- Treasury имеет минимальные резервы (не может обанкротиться).
- Доля сделок с AI/TREASURY пишется в метрики.
- Старые заявки агентов отменяются или обновляются, чтобы стакан не засорялся.
- Нельзя обещать пользователю доходность из-за действий агентов.

## 11. Что надо решить перед кодом

- Используем `USD` как фиат и `USDT` как расчётную валюту крипто-спота; добавляем мост `USD/USDT`.
- Крипто-пары MVP: `BTC/USDT`, `ETH/USDT`, `BNB/USDT`, `SOL/USDT`, `DOGE/USDT`, `TON/USDT`.
- Для XCP запускаем сразу `XCP/USDT`, `XCP/USD` и `XCP/RUB`.
- Название `xcpInterest` оставляем.
- AI users в публичном UI выглядят как обычные участники, без отдельной маркировки.
- AI users должны уметь делать те же финансовые действия, что human user: держать счета, создавать/отменять заявки, торговать спот, переводить фиат между слоями и торговать акциями через существующие финансовые операции.
